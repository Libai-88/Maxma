# MaxmaHere 当前架构

> 现行架构的唯一总览。内容以代码、构建脚本和测试为准；冲突时以代码为准并立刻回来改本文。
> 迁移过程、方案与实验记录不属于本文（旧文档已删除，需要时用 `git log --diff-filter=D -- <路径>` 取回）。

## 1. 定位与唯一执行路径

本地优先 AI Agent 客户端，两种分发形态：Web 便携包（后端托管 `web/dist`）与 Electron 桌面便携包（同一套后端产物的窗口壳）。

```text
React 前端（web/dist）
   │ HTTP + WebSocket
   ▼
Bun 后端（bun-backend，Hono）
   │ in-process 直接函数调用
   ▼
pi 引擎（bun-sidecar/src/kernel，@earendil-works/pi-coding-agent 1.5.0）
   ├── LLM Provider（含插件注册的渠道）
   ├── 内置工具 + Maxma 自定义工具
   └── MCP 服务器
```

引擎以库形式被后端调用：没有跨进程 JSON-RPC/stdio 层，没有 Python 后端，没有 Tauri 壳。**Agent 推理与工具循环只在 kernel 里执行，不要在别处重写。**

### Workbench 2.0（P0–P3 + 2026-11-21 收口）

对话页右侧工作台由 `web/src/components/workbench/WorkbenchHost.tsx` 承载。Pane 顺序/中文名/桥依赖/
布局策略/组件加载器只在 `workbench/panes.ts` 声明：「推理 / 任务 / 画布 / 文件 / 变更 / 命令 / 浏览器」；宿主
按注册表把 Pane 映射成 `React.lazy` 组件，不再保留 `activeTab === ...` 或 tab 专属 padding 分支，首次访问才加载。
顶部入口不再把七个 Pane 横排：只显示一个当前面板主标签（`aria-haspopup="dialog"`）与右侧 `+`，两者打开同一个
按「对话 / 设计 / 工作区 / 网页」分组的纵向面板库；`panes.ts` 同时声明每项的 `group/summary/icon`，弹层打开时并入
`overlayOpen` 隐藏原生浏览器层，避免原生 view 盖住菜单。每个 Pane 只依赖 `paneProps.ts` 的统一上下文。已访问 Pane 按会话保活，关闭工作台只隐藏不卸载，草稿与命令输出
不丢；每个 Pane 有独立错误边界。左侧 `Sidebar` 是全局路由，右侧 Workbench 是会话级上下文，两者职责分离，不合并成第二套导航。
画布 Pane 是 Konva 驱动的**设计画板**（`design/DesignCanvasPane.tsx` + `CanvasStage` + `CanvasLayers` +
`CanvasInspector`）：画板预设、五类元素、选择/变换、吸附参考线、图层、属性、图片导入/替换、PNG 导出与
`maxma:add-image-ref` 发回对话；项目按会话存 IndexedDB（`maxma-design-canvas` 的 `projects`/`assets`），旧
code/table 产物卡片收进画布内「资料」抽屉，不再充当画布主体。画布也由 Agent 接管：
`canvas_read`/`canvas_apply`/`canvas_export` 经 `canvasCommandBroker` 发 `canvas_command` 到当前会话的真实
`DesignCanvasPane` 执行，再以 `canvas_agent_result` 回执；批量操作一次只压一条撤销，导出可落盘或进对话输入框。
文件 Pane（`FilesPane.tsx` + `FileTree` + `FileEditor` + `FilePreview`）支持懒加载、过滤、递归文件名搜索、
多文件 tab、CodeMirror 编辑与 `base_hash` 冲突保存；变更 Pane（`ChangesPane`）读取系统 Git 的
status/diff 并可显式 stage/commit；命令 Pane 是**无 TTY 的命令运行器**（不叫终端）；任务 Pane
只投影 goal/taskTracker/planCard，不新增第二套任务状态。浏览器 Pane 用
`desktop/electron/browser-view.cjs` 的多页签 `WebContentsView`（最多 8 个，共享隔离的 `persist:maxma-browser` 会话，
只有 active 页签可见，后台页签仍可被 Agent 定向读取/操作），地址栏/前进/后退/刷新/外部打开/清除数据齐全，
并支持截图标注与元素拾取回填。下载由 `will-download` 固定写入 `<data>/downloads`，文件名经 `browser-downloads.cjs`
清洗、同名编号、单文件 512 MiB 上限，UI 可查看进度并在文件夹中定位；网络策略由 `browser-net-policy.cjs`
持久化到 `<data>/api/data/browser-policy.json`，默认全放行，可切 allowlist 按域名/子域/IP 拦截 HTTP(S)
主请求和子资源，Agent 无修改入口。浏览器 Agent 经
`browser-agent-server.cjs`（loopback + 随机 secret + 双层动作白名单 + `request_id` 去重）到 view；
`browser-cdp.cjs` 用 Chromium CDP 无障碍树生成 ref，并以真实鼠标/键盘事件执行 click/fill/press/select/
check/drag/upload/scrollIntoView/wait/evaluate；attach 时开启 `Emulation.setFocusEmulationEnabled`，键盘走
CDP `keyDown`/`keyUp`，不依赖宿主窗口是否被终端抢焦点；click 还支持 `x/y` 视口坐标视觉定位，upload 用
`DOM.setFileInputFiles` 写真实 file input。`browser_navigate`/`browser_read`/`browser_act` 都进入 pi 会话活动工具表，
并支持 `newTab`/`tabId`、`tabs`/`downloads` 读取与 `closeTab`。
并行会话 tab 最多 3 个，切 tab 不主动断 WS。工作台支持拖拽调宽、最大化与 `Ctrl/⌘+P` 命令面板；
窄窗改为覆盖聊天区整宽。纯 Web 形态没有 preload，只显示推理/任务/画布，文件、变更、命令与浏览器入口直接不出现。
工作区根同时是文件面板授权与 Agent 文件工具的 PathPolicy 根；用户还可以额外追加路径 allowlist。
PathPolicy 只放行这些根内的路径，并在工具执行前拒绝绝对越界、UNC、`..`、符号链接等；它不是 OS 沙箱，
安全边界与降级项见 [security-contract.md](security-contract.md)。

### M2–M4 能力（2026-11-21）

**代码智能（C1–C4）**：`bun-sidecar/src/codeintel/{store,symbols,service}.ts` 建 SQLite FTS5 索引，默认
`<data>/api/data/code-index.db`；REST `GET /api/code-index/status|search|symbols|definition|references`、
`POST /api/code-index/build|cancel|diagnostics`。Agent 工具面是 `code_search`、`code_symbols`、
`code_definition`、`code_references`、`code_diagnostics`、`code_apply_patch`；前五个只读，
`code_apply_patch` 一次最多 20 个文件/单文件 8 MiB，先全部预检（存在性、精确匹配、符号链接与越界），
再临时文件 + rename，失败按备份回滚；可选 `verify=typecheck` 失败同样回滚。它是进程内事务，
不是崩溃一致性保证，长期备份仍由审计快照负责。

**任务图与子 Agent（A1/A2）**：`kernel/task-graph.ts` 是纯状态机（最多 16 个任务、依赖环/未知依赖拒绝、
依赖全部成功才 ready、失败级联阻塞下游、重试 0–3、取消与快照）；`kernel/subagent.ts` 按图调度，
失败只阻塞下游，重试重建子会话，结果按输入顺序返回，details 带 `graph`/`counts`。可写子 Agent 默认
在 `os.tmpdir()/maxma-subagent-worktrees` 的隔离 worktree 中工作，不直接改主工作区。

**生命周期 Hooks（A4）**：`kernel/hooks/{hook-types,config,runner,audit}.ts` + `kernel/extensions/maxma-hooks.ts`。
配置默认 `<data>/config/hooks.json`（`MAXMA_HOOKS_FILE` 可覆盖），整份列表用同目录 `hooks.secret` 做
HMAC-SHA256 签名；签名缺失/不匹配整份不加载。事件映射为 `PreToolUse→tool_call`、`PostToolUse→tool_result`、
`SessionStart→session_start`、`SessionEnd→session_shutdown`、`PreCompact→session_before_compact`。
处理器只有三种：`command`（不经过 shell，stdin 收 JSON payload）、`http`（仅 POST http(s)，拒绝带凭据 URL）、
`prompt`（不调模型；PreToolUse 作拒绝原因，其它事件作附加上下文）。钩子在 blocker/path-policy **之前**运行，
因此钩子改写的入参仍会被 PathPolicy 复检；坏钩子 fail-open 并写 `<data>/api/data/hooks_audit.jsonl`。

**三层记忆（MEM-1）**：`bun-backend/src/services/memory-store.ts` 把 persona 存
`<data>/config/personas/memory.yaml`、project 存 `<data>/memory/projects/<key>.yaml`、session 存
`<data>/memory/sessions/<key>.jsonl`；`routes/memory.ts` 支持 `?scope=`、分层 stats、任意层写入、
导出/导入（`merge`/`replace`）与冲突列表，冲突日志落 `<data>/memory/conflicts.jsonl`。Agent 侧有
`search_memories`/`remember_memory`/`merge_memories` 三个工具，UI 为 `MemoryView.tsx` 的三层 tab、
scope 筛选、导出下载与导入合并。

**Office 读写（OFF-1）**：`bun-sidecar/src/tools/office.ts` 的 `read_office_file`/`write_office_file`。
DOCX 读取解析 `word/styles.xml` 的标题样式、加粗/斜体与图片关系；写入支持 `#`–`###` 标题与 `-` 列表
生成 Heading1–3。XLSX 支持多工作表读取与写入；单文件上限 20 MiB，所有路径先限制在工作区内。

**Office 预览（M2-A）**：`web/src/components/workbench/OfficePreview.tsx` 只读渲染 DOCX/XLSX/PPTX；
`GET /api/workspace/watch` 对当前预览文件做目录级监听，300ms 去抖后经 SSE 推送 `ready`/`file`，
`FilesPane` 收到后重新拉取 blob。预览不接管编辑，避免用户草稿与 Agent 写入互相覆盖。

**画布 SVG 与模板（CAN-1）**：`web/src/components/workbench/design/canvasSvg.ts` 提供常用 SVG 子集的
导入/导出与画板模板；`DesignCanvasPane` 把工具轨数据拆到 `DesignCanvasRail.tsx`，纯展示与纯数据不占主面板体量。
导入只接受受支持的 SVG 元素，不支持 path/gradient，避免把任意 SVG 当成可编辑元素静默降级。

**上下文总线（C5）**：`web/src/context/{contextItems,contextBus}.ts` 统一 9 种 `ContextItem`，
正文按 8000 字符截断、最多 20 条、按 id 去重，并按会话写 `localStorage` 快照
`maxma.context.<sessionId>`。`ChatInput`、`FilesPane`、`BrowserPane`、`DesignCanvasPane` 已接线；
它只是前端会话级引用清单，不是后端持久化会话状态。

**本地模型接入与回退（MOD-1）**：`POST /api/models/local-setup` 支持 `preset=ollama`
（`http://127.0.0.1:11434/v1`）与 `preset=lmstudio`（`http://127.0.0.1:1234/v1`），也接受自定义
`base_url` 但只允许本机地址。先探测 OpenAI 兼容 `/models`：不可达返回 409 `LOCAL_MODEL_UNREACHABLE`
且不写 `providers.yaml`，可达但无模型返回 409 `LOCAL_MODEL_EMPTY`；成功时新建或复用同 `base_url` 的渠道。
`chat-ws` 在开轮前只对本机渠道做一次预检（探测缓存成功 60s/失败 30s），不可达时优先切到有 `api_key` 的
非本机渠道，否则再试另一台可达的本机服务；只回退一次，成功后广播 `model_fallback` 并更新回合
provider/model。成本面板读 `/api/metrics/llm-usage` 的 `cost_total`/`cost_known_calls`/`cost_unknown_calls`，
未知单价不当 0，合计可显示“未知”。

**研究、Git 与硬件**：`web_search`/`web_fetch` 是 Agent 一等工具（网页搜索解析与抓取有独立测试）；
Git 交付走 `services/git-service.ts` + `routes/git.ts` 的 status/diff/stage/unstage/commit/push/PR，
全部 async `spawn`、路径加 `:(literal)`、commit 必须 `confirm:true`。`services/hardware.ts` 提供
CPU/内存/GPU 探针与 `GET /api/system/hardware`、`GET /models/routing`，只做本机能力评估，不代替模型调用。

## 3. 引擎接缝：`pi-contract.ts`

`bun-sidecar/src/kernel/pi-contract.ts` 是 **Maxma 向引擎借用名字的单一数据源**：导出符号、事件名、内置工具、ThinkingLevel、provider api、settings 点路径、RPC 方法名，以及 `ENGINE_EVENT_EXPECTED_BUT_UNPRODUCED`（引擎不产出事件的登记表，带原因与处置）。

由两个测试对账**已安装的引擎包**：`tests/pi-contract.test.ts`（差集校验）、`tests/engine-boundary.test.ts`（边界纪律 + 事件生产者双向对账 + 两 workspace 版本与两把锁一致）。

**新增任何对引擎名字的依赖，必须先在此登记，否则守卫红。** 契约文档不再维护副本。

`tests/contract-snapshot.test.ts` 只锁"我方映射不回归"（喂手写合成事件），**测不出上游改名**，与上面两者互补，不可替代。

## 4. 一次对话的生命周期

1. `GET /api/auth/token` 取运行时 Token（存 `maxma.db` 的 `auth_tokens` 表）。
2. 连 `/ws/chat/{session_id}`，Token 放 WS subprotocol（回退 header/query）。
3. 后端校验后 `create_session`（复用 `server.ts` 的 `hubSessions`）。
4. 用户消息经 `prompt` 进 pi。
5. kernel 把 token/thinking/tool/ask_user/plan/answer/done/error 推给后端。
6. `chat-ws.ts` 的 `onKernelEvent` 富化（turn_id、截断、artifact、memory、埋点）后广播。
7. 回合结束更新消息计数；前端存可恢复的 UI turn 缓存（`localStorage` 键 `maxma_turns_<session_id>`）。

取消/断线必须经 kernel `cancel`。

## 5. 持久化

路径解析集中在 `bun-backend/src/app-paths.ts`（惰性 getter，`MAXMA_DATA_DIR` / `MAXMA_BUNDLE_DIR` / `MAXMA_EXE_DIR` 可覆盖）：

| 形态 | 只读资源 | 可写数据 |
| --- | --- | --- |
| 开发 | 项目根 | 项目根 |
| 便携 | `MAXMA_BUNDLE_DIR` | 可执行文件旁 `data/`（`portable.flag` 标记） |
| 标准 | 打包资源目录 | `%APPDATA%\MaxmaHere` |

常用可写数据在数据目录的 `api/data/`：`providers.yaml`（API Key 信封加密）、`mcp_servers.yaml`、`credential.key`、`maxma.db`（auth_tokens / sessions / rules / metrics / collab…）、`settings_overrides.json`、`panel_configs.json`、`news.yaml`、`plugins/`、`code-index.db`、`hooks_audit.jsonl`；另有 `config/personas/`（含 `memory.yaml`）、`config/hooks.json` 与 `hooks.secret`、`memory/projects/`、`memory/sessions/`、`memory/conflicts.jsonl`、`macros/`、`uploads/`、`logs/`。

**不要把用户运行时数据打进构建产物。**

### 5.1 会话历史（重启可恢复）

pi 的会话以 JSONL 存在 `PI_CODING_AGENT_DIR/sessions/<cwd 编码>/*.jsonl`。Maxma 的
`/api/sessions` 只列**本进程内存 hub**；重启后这些 JSONL 由
`kernel/session-catalog.ts` 扫描出来，经 `GET /api/sessions/history` 提供给前端，
`POST /api/sessions/:id/resume` 用官方 `SessionManager.open(file)` 接回 hub（id 沿用原
id，前端 turns 缓存与 WS 直接复用）。新建会话时 pi header id 显式等于 hub id
（`NewSessionOptions.id`），否则"按 id 恢复"对不上。删除会话会同时删内存记录与
磁盘文件（`delete_persisted_session`），避免删掉的会话在历史列表里复活。

引擎自己的配置目录由 `PI_CODING_AGENT_DIR` 决定（pi 用 `${APP_NAME.toUpperCase()}_CODING_AGENT_DIR` 拼名，回落 `~/.pi/agent`）。该变量名由上游拼接，**改名会让注入静默失效**，因此 `kernel/engine-info.ts` 的 `agentDirDiagnostics()` 在启动时验结果（问 `getAgentDir()` 实际落在哪、是否在 Maxma 数据目录内），状态暴露在 `/api/health` 的 `engine` 字段与 `/api/capabilities` 的 `engine.agent_dir_inside_expected`（**仅信息字段，不参与 overall 判定**——开发形态下用 `~/.pi/agent` 是正常的）。桌面壳读到 `false` 才弹错误框。

## 6. Provider / 工具 / Skill / MCP

- **Provider**：`routes/providers.ts`，Key 走 `security/credential-envelope.ts`（Fernet 兼容），前端只拿脱敏值；`base_url` 保存与请求前均校验。内置免费渠道见 `kernel/opencode-zen.ts`（端点、请求头形状、候选兜底链由 `bun-sidecar/tests/opencode-fallback-chain.test.ts` 锁定）。本机模型一键接入走 `routes/hardware.ts` 的 `POST /api/models/local-setup`（只探测 loopback `/models`，不可达不落盘）；开轮回退与成本口径见 `services/model-fallback.ts`、`llm-usage-ledger.ts`。
- **工具**：内置由 pi 提供，Maxma 启用的默认集与自定义工具清单见 `pi-contract.ts`（`MAXMA_ENABLED_DEFAULT_TOOLS` / `MAXMA_CUSTOM_TOOLS`）；实现在 `bun-sidecar/src/tools/`，前端展示清单在 `routes/tools.ts`；工具结果在 `web/src/components/chat/ChatWindow.tsx` 统一渲染为「步骤 + 输出/补丁」，中文展示名见 `web/src/components/tools/_shared/displayNames.ts`。
- **Skill**：`.maxma/skills/`（随包）+ 工作区与用户目录 `.agents/skills/`，由 `kernel/skills.ts` `maxmaSkillPaths()` 传给 pi。
- **MCP**：`routes/mcp.ts` + `kernel/mcp.ts`，stdio 命令过 `routes/mcp-validation.ts` 白名单；配置变更后需 `reload_mcp_for_session` 或新建会话。

## 7. 插件子系统

内置插件 `codearts-auth`（展示名 **Jet Hub**），默认启用，`kind: "dsh"`。

```text
JetHubView.vue → POST /api/jet-hub → plugins/dsh/http-bridge.ts（通用转发）
  → dsh-codearts-auth 的 jet-hub-rpc 分派器 → pi-bridge/pi-providers
  → pi ModelRuntime.registerProvider → 出现在模型选择器
```

两条不可省略的约束（真机踩过，有回归测试）：

1. `chat-ws` 对 `providers.yaml` 里查不到的 provider 必须回落到 `isPluginProvider()`，且**不传** baseUrl / apiKey / providerType。
2. 注册自定义 provider **必须带 baseUrl**（pi 拒绝无 baseUrl 的自定义模型），刻意用保留域 `https://plugin.invalid/<route>` 让误用响亮失败。

插件数据落 Maxma 数据目录 `plugins/`（注入 `DSH_HOME` / `DSH_JET_HUB_STATE_DIR`），不写 `~/.dsh`。方法面覆盖由 `bun-backend/tests/plugins/jet-hub-coverage.test.ts` 从插件分派器现读方法名做差集守卫。

**网络安装面刻意未开**：`POST /api/plugins/install` 只启用已随包分发的插件，未知插件拒绝（501）；`PluginListView.tsx` 的安装框按 `features.plugins.marketplace` 分支，`false` 时不再显示 npm/GitHub 安装入口。

## 8. 能力门控

`routes/capabilities.ts` `buildManifest()` 聚合 settings/工具/MCP/Provider/配置源 + `features` 清单；前端 `src/router.tsx` 的 `FeatureGate` 守卫 + `components/layout/Sidebar.tsx` 条目过滤消费它，禁用能力落 `FeatureUnavailableView`。

**已删除的能力项**（2026-11-12 复核，pi 既无机制也无第二路线）：`automation`（调度器）、
`browser_tools`（浏览器运行时）。门控项、路由、设置面板、DB 表一并清掉；浏览器自动化改走
MCP（pi 官方 mcp 文档，由扩展页的市场安装）。

**当前可用但受用户开关控制**：`sub_agents`（pi 支持 → SDK 进程内子会话，`kernel/subagent.ts`，
`mechanism="pi-sdk-in-process"`）、`tts`（浏览器 `speechSynthesis`，非引擎能力）、`plugins.marketplace`（安全评审未过，恒 false）。

**产品开关 ≠ 引擎能力**，两者分开表达（`enabled` 只代表用户意图，`engine_supported` 代表引擎是否可能支持），勿复用 `enabled` 判引擎支持度。
子 Agent 的 `engine_supported` 自 2026-11-12 起为 true——此前为 false 是把上一代 deferred 面的缺失
当成了 pi 的事实（pi 官方示例 `examples/extensions/subagent` 与 pi 官方 SDK 文档 都给了做法）。

前端把这条区分走到底，判定集中在 `web/src/stores/capabilities.ts` 的
`describeFeatureAvailability(features, name)`（`engine_unsupported` / `user_disabled` /
`not_deployed` / `manifest_unloaded` / `available`）：

- `FeatureUnavailableView` 按 kind 分说法并原样显示后端 `reason`，不再把"引擎做不到"说成"你关掉了"；
- `SettingsView` 对"写了没人读"的面板置灰且**写入函数直接 return**（置灰不是装饰）。
  2026-11-12 之后这类面板已清零：`browser_tools` 删除，`sub_agents` 的每个控件都由
  `kernel/subagent.ts` 真消费（开关/并行/超时）；
- `AppSettingsMenu` 与 `Dock` 一样按 `feature` 过滤入口，禁用能力不再留下会跳"功能不可用"的菜单项。

**新增面板时必须同步这张判定表**——一个运行时不读的控件对用户就是谎言。

## 9. 安全边界

见 [security-contract.md](security-contract.md)。要点：MaxmaBlocker 拒止锚 + PathPolicy（工作区根/allowlist）+ 三值权限矩阵 + 命令守卫（policy-only，非 OS 沙箱）+ 工具审计/写入快照 + MCP 命令白名单 + Provider URL 校验 + 凭据信封加密 + Token 鉴权 + 限流 + CORS 精确 origin；异常一律视为拒绝；Token 不进前端产物、Key 不进日志。
