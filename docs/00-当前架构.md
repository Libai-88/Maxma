# MaxmaHere 当前架构

> 现行架构的唯一总览。内容以代码、构建脚本和测试为准；冲突时以代码为准并立刻回来改本文。
> 迁移过程、方案与实验记录不属于本文（旧文档已删除，需要时用 `git log --diff-filter=D -- <路径>` 取回）。

## 1. 定位与唯一执行路径

本地优先 AI Agent 客户端，两种分发形态：Web 便携包（后端托管 `web/dist`）与 Electron 桌面便携包（同一套后端产物的窗口壳）。

```text
React 前端（web/dist）
   │ HTTP + WebSocket
   ▼
Bun 后端（bun-backend，Hono）
   │ in-process 直接函数调用
   ▼
pi 引擎（bun-sidecar/src/kernel，@earendil-works/pi-coding-agent 0.99.0）
   ├── LLM Provider（含插件注册的渠道）
   ├── 内置工具 + Maxma 自定义工具
   └── MCP 服务器
```

引擎以库形式被后端调用：没有跨进程 JSON-RPC/stdio 层，没有 Python 后端，没有 Tauri 壳。**Agent 推理与工具循环只在 kernel 里执行，不要在别处重写。**

## 3. 引擎接缝：`pi-contract.ts`

`bun-sidecar/src/kernel/pi-contract.ts` 是 **Maxma 向引擎借用名字的单一数据源**：导出符号、事件名、内置工具、ThinkingLevel、provider api、settings 点路径、RPC 方法名，以及 `ENGINE_EVENT_EXPECTED_BUT_UNPRODUCED`（引擎不产出事件的登记表，带原因与处置）。

由两个测试对账**已安装的引擎包**：`tests/pi-contract.test.ts`（差集校验）、`tests/engine-boundary.test.ts`（边界纪律 + 事件生产者双向对账 + 两 workspace 版本与两把锁一致）。

**新增任何对引擎名字的依赖，必须先在此登记，否则守卫红。** 契约文档不再维护副本。

`tests/contract-snapshot.test.ts` 只锁"我方映射不回归"（喂手写合成事件），**测不出上游改名**，与上面两者互补，不可替代。

## 4. 一次对话的生命周期

1. `GET /api/auth/token` 取运行时 Token（存 `maxma.db` 的 `auth_tokens` 表）。
2. 连 `/ws/chat/{session_id}`，Token 放 WS subprotocol（回退 header/query）。
3. 后端校验后 `create_session`（复用 `server.ts` 的 `hubSessions`）。
4. 用户消息经 `prompt` 进 pi。
5. kernel 把 token/thinking/tool/ask_user/plan/answer/done/error 推给后端。
6. `chat-ws.ts` 的 `onKernelEvent` 富化（turn_id、截断、artifact、memory、埋点）后广播。
7. 回合结束更新消息计数；前端存可恢复的 UI turn 缓存（`localStorage` 键 `maxma_turns_<session_id>`）。

取消/断线必须经 kernel `cancel`。

## 5. 持久化

路径解析集中在 `bun-backend/src/app-paths.ts`（惰性 getter，`MAXMA_DATA_DIR` / `MAXMA_BUNDLE_DIR` / `MAXMA_EXE_DIR` 可覆盖）：

| 形态 | 只读资源 | 可写数据 |
| --- | --- | --- |
| 开发 | 项目根 | 项目根 |
| 便携 | `MAXMA_BUNDLE_DIR` | 可执行文件旁 `data/`（`portable.flag` 标记） |
| 标准 | 打包资源目录 | `%APPDATA%\MaxmaHere` |

常用可写数据在数据目录的 `api/data/`：`providers.yaml`（API Key 信封加密）、`mcp_servers.yaml`、`credential.key`、`maxma.db`（auth_tokens / sessions / rules / metrics / collab…）、`settings_overrides.json`、`panel_configs.json`、`news.yaml`、`plugins/`；另有 `config/personas/`、`macros/`、`uploads/`、`logs/`。

**不要把用户运行时数据打进构建产物。**

### 5.1 会话历史（重启可恢复）

pi 的会话以 JSONL 存在 `PI_CODING_AGENT_DIR/sessions/<cwd 编码>/*.jsonl`。Maxma 的
`/api/sessions` 只列**本进程内存 hub**；重启后这些 JSONL 由
`kernel/session-catalog.ts` 扫描出来，经 `GET /api/sessions/history` 提供给前端，
`POST /api/sessions/:id/resume` 用官方 `SessionManager.open(file)` 接回 hub（id 沿用原
id，前端 turns 缓存与 WS 直接复用）。新建会话时 pi header id 显式等于 hub id
（`NewSessionOptions.id`），否则"按 id 恢复"对不上。删除会话会同时删内存记录与
磁盘文件（`delete_persisted_session`），避免删掉的会话在历史列表里复活。

引擎自己的配置目录由 `PI_CODING_AGENT_DIR` 决定（pi 用 `${APP_NAME.toUpperCase()}_CODING_AGENT_DIR` 拼名，回落 `~/.pi/agent`）。该变量名由上游拼接，**改名会让注入静默失效**，因此 `kernel/engine-info.ts` 的 `agentDirDiagnostics()` 在启动时验结果（问 `getAgentDir()` 实际落在哪、是否在 Maxma 数据目录内），状态暴露在 `/api/health` 的 `engine` 字段与 `/api/capabilities` 的 `engine.agent_dir_inside_expected`（**仅信息字段，不参与 overall 判定**——开发形态下用 `~/.pi/agent` 是正常的）。桌面壳读到 `false` 才弹错误框。

## 6. Provider / 工具 / Skill / MCP

- **Provider**：`routes/providers.ts`，Key 走 `security/credential-envelope.ts`（Fernet 兼容），前端只拿脱敏值；`base_url` 保存与请求前均校验。内置免费渠道见 `kernel/opencode-zen.ts`（端点、请求头形状、候选兜底链由 `bun-sidecar/tests/opencode-fallback-chain.test.ts` 锁定）。
- **工具**：内置由 pi 提供，Maxma 启用的默认集与自定义工具清单见 `pi-contract.ts`（`MAXMA_ENABLED_DEFAULT_TOOLS` / `MAXMA_CUSTOM_TOOLS`）；实现在 `bun-sidecar/src/tools/`，前端展示清单在 `routes/tools.ts`；工具结果在 `web/src/components/chat/ChatWindow.tsx` 统一渲染为「步骤 + 输出/补丁」，中文展示名见 `web/src/components/tools/_shared/displayNames.ts`。
- **Skill**：`.maxma/skills/`（随包）+ 工作区与用户目录 `.agents/skills/`，由 `kernel/skills.ts` `maxmaSkillPaths()` 传给 pi。
- **MCP**：`routes/mcp.ts` + `kernel/mcp.ts`，stdio 命令过 `routes/mcp-validation.ts` 白名单；配置变更后需 `reload_mcp_for_session` 或新建会话。

## 7. 插件子系统

内置插件 `codearts-auth`（展示名 **Jet Hub**），默认启用，`kind: "dsh"`。

```text
JetHubView.vue → POST /api/jet-hub → plugins/dsh/http-bridge.ts（通用转发）
  → dsh-codearts-auth 的 jet-hub-rpc 分派器 → pi-bridge/pi-providers
  → pi ModelRuntime.registerProvider → 出现在模型选择器
```

两条不可省略的约束（真机踩过，有回归测试）：

1. `chat-ws` 对 `providers.yaml` 里查不到的 provider 必须回落到 `isPluginProvider()`，且**不传** baseUrl / apiKey / providerType。
2. 注册自定义 provider **必须带 baseUrl**（pi 拒绝无 baseUrl 的自定义模型），刻意用保留域 `https://plugin.invalid/<route>` 让误用响亮失败。

插件数据落 Maxma 数据目录 `plugins/`（注入 `DSH_HOME` / `DSH_JET_HUB_STATE_DIR`），不写 `~/.dsh`。方法面覆盖由 `bun-backend/tests/plugins/jet-hub-coverage.test.ts` 从插件分派器现读方法名做差集守卫。

**网络安装面刻意未开**：`POST /api/plugins/install` 只启用已随包分发的插件，未知插件拒绝（501）；`PluginListView.tsx` 的安装框按 `features.plugins.marketplace` 分支，`false` 时不再显示 npm/GitHub 安装入口。

## 8. 能力门控

`routes/capabilities.ts` `buildManifest()` 聚合 settings/工具/MCP/Provider/配置源 + `features` 清单；前端 `src/router.tsx` 的 `FeatureGate` 守卫 + `components/layout/Sidebar.tsx` 条目过滤消费它，禁用能力落 `FeatureUnavailableView`。

**已删除的能力项**（2026-11-12 复核，pi 既无机制也无第二路线）：`automation`（调度器）、
`browser_tools`（浏览器运行时）。门控项、路由、设置面板、DB 表一并清掉；浏览器自动化改走
MCP（pi 官方 mcp 文档，由扩展页的市场安装）。

**当前可用但受用户开关控制**：`sub_agents`（pi 支持 → SDK 进程内子会话，`kernel/subagent.ts`，
`mechanism="pi-sdk-in-process"`）、`tts`（浏览器 `speechSynthesis`，非引擎能力）、`plugins.marketplace`（安全评审未过，恒 false）。

**产品开关 ≠ 引擎能力**，两者分开表达（`enabled` 只代表用户意图，`engine_supported` 代表引擎是否可能支持），勿复用 `enabled` 判引擎支持度。
子 Agent 的 `engine_supported` 自 2026-11-12 起为 true——此前为 false 是把上一代 deferred 面的缺失
当成了 pi 的事实（pi 官方示例 `examples/extensions/subagent` 与 pi 官方 SDK 文档 都给了做法）。

前端把这条区分走到底，判定集中在 `web/src/stores/capabilities.ts` 的
`describeFeatureAvailability(features, name)`（`engine_unsupported` / `user_disabled` /
`not_deployed` / `manifest_unloaded` / `available`）：

- `FeatureUnavailableView` 按 kind 分说法并原样显示后端 `reason`，不再把"引擎做不到"说成"你关掉了"；
- `SettingsView` 对"写了没人读"的面板置灰且**写入函数直接 return**（置灰不是装饰）。
  2026-11-12 之后这类面板已清零：`browser_tools` 删除，`sub_agents` 的每个控件都由
  `kernel/subagent.ts` 真消费（开关/并行/超时）；
- `AppSettingsMenu` 与 `Dock` 一样按 `feature` 过滤入口，禁用能力不再留下会跳"功能不可用"的菜单项。

**新增面板时必须同步这张判定表**——一个运行时不读的控件对用户就是谎言。

## 9. 安全边界

见 [security-contract.md](security-contract.md)。要点：MaxmaBlocker 拒止锚 + 审批门 + MCP 命令白名单 + Provider URL 校验 + 凭据信封加密 + Token 鉴权 + 限流 + CORS 精确 origin；异常一律视为拒绝；Token 不进前端产物、Key 不进日志。
