# MaxmaHere 当前架构

> 本文档是项目现行架构的唯一总览。内容以当前代码、构建脚本和测试为准，不记录迁移过程，也不保留已删除实现的操作说明。
>
> 更新时间：2026-10-01

## 1. 项目定位

MaxmaHere 是一个本地优先的 AI Agent 客户端，当前以 **Web 形态**分发（后端进程内托管前端静态资源，浏览器访问）。Maxma 负责会话管理、配置持久化、前后端通信和安全边界；pi 引擎负责 Agent 推理循环、模型调用和工具执行。

Agent 执行路径只有一条：

```text
Vue 前端（web/dist，由后端托管）
        |
        | HTTP + WebSocket
        v
Bun 后端（bun-backend，Hono）
        |
        | 直接函数调用（kernel in-process）
        v
pi 引擎（bun-sidecar/src/kernel，@earendil-works/pi-coding-agent）
        |
        +-- LLM Provider
        +-- 内置工具
        +-- Maxma 自定义工具
        +-- MCP 服务器
```

引擎以库形式被后端直接调用（in-process），不再有跨进程 JSON-RPC stdio 层，也没有独立的 Python 后端。不要在别处重新实现 Agent 循环。

## 2. 分层职责

### 2.1 Vue 前端：`web/`

入口：`web/src/main.ts`、`web/src/App.vue`

职责：

- 页面、路由、主题和设计系统
- Pinia 状态管理
- REST API 调用和 Token 获取
- 每个会话独立的 WebSocket 连接
- token、工具、审批、计划和错误事件的渲染

关键位置：

- `web/src/router/index.ts`：页面路由（带 `meta.feature` 能力守卫，禁用能力重定向到 `FeatureUnavailableView`）
- `web/src/api/index.ts`：REST 客户端
- `web/src/composables/useChat.ts`：聊天 WebSocket 生命周期
- `web/src/stores/`：session / chat / memory / provider / persona / capabilities / health 等
- `web/src/components/tools/registry.ts`：工具结果组件路由

### 2.2 Bun 后端：`bun-backend/`

入口：`bun-backend/src/server.ts`（`createApp()` 装配 Hono + `startServer()` 绑定 Bun.serve）

职责：

- HTTP 路由与 WebSocket 端点（`/api/**`、`/ws/chat/{session_id}`）
- Token 鉴权、CORS、限流、请求日志中间件
- Maxma session 生命周期与 REST CRUD
- 前端 WebSocket 与 kernel 事件之间的桥接与回合富化
- Provider、MCP、Skill、Macro、人设、记忆、规则等持久化
- 凭据加密（Fernet 兼容）、路径安全、MaxmaBlocker
- Web 形态静态文件托管（`web/dist`，SPA fallback）

对话核心入口：`bun-backend/src/routes/chat-ws.ts`（WS 消息分发 + `onKernelEvent` 回合富化）。REST 会话门面：`bun-backend/src/routes/sessions.ts`。两者经 `server.ts` 的 `callKernelRpc` 直接调用 kernel。

后端读取 `bun-sidecar/src/kernel/bridge-pi.ts` 的 `handlePiCreateSession` / `handlePiSessionRpc`（in-process）。

### 2.3 pi 引擎：`bun-sidecar/src/kernel/`

入口：`bun-sidecar/src/kernel/bridge-pi.ts`（RPC 分发 + 会话装配）

职责：

- 创建并维护 pi `AgentSession`（`@earendil-works/pi-coding-agent` 官方 API）
- 解析 provider/model 配置
- 注册 Maxma 自定义工具（`bun-sidecar/src/tools/`）
- 加载并连接 MCP 服务器
- 执行 prompt、cancel、undo、compact、消息读取、计划/审批/目标/检查点
- 将 pi 事件映射为 Maxma 事件（`kernel/events.ts`）
- 在审批模式下等待前端确认（`kernel/approval-gate.ts`）

kernel 支持的 RPC 方法（经后端直接调用）：`create_session` / `prompt` / `cancel` / `destroy_session` / `undo` / `compact` / `get_messages` / `get_health` / `user_response` / `get_settings` / `set_settings` / `set_auto_approve` / `set_plan_mode` / `plan_action` / `checkpoint_action` / `goal_action` / `get_goal_state` / `reload_mcp_for_session` / `execute_workflow_step`。

> `bun-sidecar/src/session-bridge.ts` 是旧的 stdio JSON-RPC 进程入口，当前无运行时调用方（仅契约测试引用）；引擎能力全部经 kernel 以库形式暴露给后端。

### 2.4 分发形态：Web

Tauri 桌面壳已移除。当前分发为自包含 Web 便携包：`bun.exe` + 打包后的 `server.js` + 前端 `web/dist` + 运行资源，由启动器（`MaxmaHere.bat`）拉起后端进程并托管前端，浏览器访问本地端口。

## 3. 一次对话的生命周期

1. 前端通过 `/api/auth/token` 获取运行时 Token。
2. 前端连接 `/ws/chat/{session_id}`，Token 放入 WebSocket subprotocol（或 header/query）。
3. 后端校验 Token，创建或复用 kernel 会话（`create_session`）。
4. 用户消息经 `prompt` 进入 pi 引擎。
5. kernel 把 token、thinking、tool、ask_user、plan、answer、done、error 事件推给后端。
6. 后端 `onKernelEvent` 富化（turn_id、截断、artifact、memory、deferred、埋点）后广播到当前 WebSocket；前端更新对应 Pinia channel。
7. 回合完成后，后端更新消息计数与会话数据；前端保存可恢复的 UI turn 缓存。

取消和断线必须经过 kernel `cancel`。不要只取消前端任务，否则 Agent 可能继续运行并消耗模型配额。

## 4. 状态与持久化

### 4.1 会话

- 内存会话注册表：`server.ts` 的 `hubSessions`（`Map<session_id, PiSessionRecord>`）
- 常驻会话：`bun-backend/src/const-session-store.ts`
- 前端 UI turn：`localStorage`，键名 `maxma_turns_<session_id>`

### 4.2 用户数据路径

路径解析集中在 `bun-backend/src/app-paths.ts`（惰性 getter）：

| 场景 | 资源（只读） | 可写数据 |
| --- | --- | --- |
| 开发模式 | 项目根目录 | 项目根目录 |
| 便携模式 | 可执行文件旁（`MAXMA_BUNDLE_DIR`） | 可执行文件旁 `data/`（`portable.flag` 标记） |
| 标准模式 | 打包资源目录 | `%APPDATA%\MaxmaHere` |

常用可写数据（位于数据目录的 `api/data/`）：

- `api/data/providers.yaml`、`api/data/mcp_servers.yaml`、`api/data/credential.key`
- `api/data/maxma.db`（SQLite：auth_tokens / sessions / rules / metrics / collab 等）
- `config/personas/`（人设、memory.yaml）、`macros/`、`uploads/`、`logs/`

不要把用户运行时数据打进构建产物。构建只打包内置模板与运行必需资源。

## 5. Provider、工具、Skill 和 MCP

### Provider

Provider 配置由 `bun-backend/src/routes/providers.ts` 管理，存储在 `api/data/providers.yaml`。API Key 使用凭据信封加密（Fernet 兼容，`bun-backend/src/security/credential-envelope.ts`），前端只拿到脱敏结果。Provider 的 `base_url` 保存和请求前都经过 URL 校验（拒绝危险协议与云元数据地址）。

### 工具

内置 Agent 工具由 pi 引擎提供。Maxma 自定义工具在 `bun-sidecar/src/tools/` 定义并注册（`remember_memory` / `search_memories` / `get_sticker` / `list_rules` / `list_automations`）。内置工具清单见 `bun-backend/src/routes/tools.ts`。

### Skill 和 Macro

- 内置 Skill：`.omp/skills/`
- 用户 Skill：由后端写入应用数据目录
- Macro：`macros/` 与对应配置路由

### MCP

MCP 配置由 `bun-backend/src/routes/mcp.ts` 管理，kernel 在创建会话时读取 `api/data/mcp_servers.yaml` 并连接支持的 transport。stdio 命令必须通过白名单校验（`routes/mcp-validation.ts`）。修改 MCP 配置后需 `reload_mcp_for_session` 或新建会话才能生效。

## 6. 安全边界

安全边界以 [security-contract.md](security-contract.md)、[dev_docs/permission-modes.md](../dev_docs/permission-modes.md)、[dev_docs/path-whitelist.md](../dev_docs/path-whitelist.md) 和代码为准。

必须保持的原则：

- 空路径白名单默认拒绝访问
- 路径解析失败、符号链接越界和 blocker 检查异常都 fail-closed
- Token 不写入前端构建产物
- API Key 不写入日志、事件或前端响应
- MCP stdio 命令只能执行白名单内容
- Provider URL 必须拒绝危险协议和云元数据地址
- 子进程（MCP stdio）继承受限的环境变量

## 7. 开发、测试与构建

### 开发

```text
后端：cd bun-backend && bun run src/server.ts（默认 :8000）
前端：cd web && npm run dev（:5173）
一键：start.bat
```

### 测试

```text
后端：cd bun-backend && bun test
引擎：cd bun-sidecar && bun test
前端：cd web && npx vitest run
```

### 构建

```text
后端 bundle：build\build-server.bat（产出 dist\bun-server：server.js + bun.exe + sharp 原生件）
便携包：build-portable.bat（组装 Web 便携包到 ..\MaxmaHere-Portable）
便携冒烟：powershell -File build\portable-smoke-test.ps1
```

构建顺序：前端构建 → Bun 依赖安装 → bundle `server.js`（`--target bun`）→ 暂存固定版 `bun.exe` 与 sharp 原生 node_modules → 组装便携目录。打包形态为 Bun bundle（`bun.exe run server.js`），非单文件编译——sharp 原生模块（贴纸上传的图片转换）无法被 `bun build --compile` 内嵌，须随包携带。

## 10. 当前版本事实

运行时版本由 `version.py` 提供（单一数据源，后端经 `bun-backend/src/app-version.ts` 读取）；发布前检查它与 `web/package.json`、`portable.flag` 和 Git tag 一致。文档不自行推断版本号。

**当前实现边界**：

- Agent 推理和工具循环只在 pi 引擎（kernel）中执行；Bun 后端是 API、会话和安全策略层。
- 自动化功能随旧后端下线，前端路由由 capabilities 清单的 `automation.enabled=false` 做 feature 开关隐藏。
- 插件系统在当前引擎不可用（REST 桩化）；`/kb` 知识库已废弃。
- MCP 配置变更需 `reload_mcp_for_session` 或新建会话。
