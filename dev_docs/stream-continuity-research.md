# Agent 流式任务可恢复交互

研究日期：2026-10-03

## 课题边界

本课题只研究一个功能块：**Agent 在后台继续执行时，用户如何离开、返回并恢复对任务状态的感知**。

不研究通用 AGI、整体对话质量或整套 UI 设计。实现范围限定为：

- 路由切换、会话切换和窗口失焦不取消正在运行的任务；
- 会话级状态明确区分运行中、等待用户、已完成和错误；
- 用户离开对话页期间累计有限的状态事件，返回后清除未读提示；
- 不持久化提示词或完整事件流，只把已有会话数据和轻量状态用于恢复。

## 为什么值得单独研究

Agent 的“能不能完成任务”与“用户能不能持续理解任务正在发生什么”是两个不同问题。长任务中，用户可能需要查看设置、会话、模型或文件页面；如果页面切换等同于取消任务，用户就必须停留在对话页等待，这会降低 Agent 的实际可用性。

近期工作把用户在长程 Agent 执行中的追加、修改和撤回视为独立的中断类型，并指出现有 Agent 在中断后的恢复仍然困难；这说明中断和恢复本身可以作为独立的工程与评估对象，而不应只归入“聊天 UI”。另有实时人机交互研究把中断处理设计为意图识别、状态转移和反馈的组合，并在机器人实验中报告了 104/111 次中断被正确处理的结果。Maxma 当前先从更窄、风险更低的“离开页面但不打断任务”开始。

## Maxma 的可测量指标

- **任务连续率**：开始流式任务后切换页面，任务仍收到 done/error 的比例；
- **状态可见率**：用户返回前，会话列表是否显示运行中、等待用户、完成或错误；
- **恢复延迟**：返回对话页到看到最新状态的时间；
- **误取消率**：由导航或会话切换导致的非用户主动取消次数；
- **未读提示准确率**：仅在后台产生可见任务事件时增加，心跳和用量同步不计入。

## 本阶段实现

Maxma 在会话通道增加轻量状态：`streamPhase`、`unreadEvents`、`streamStartedAt` 和 `lastActivityAt`。ChatView 的 keep-alive 生命周期通过会话 presence 标记前台/后台；后台事件只增加上限为 99 的未读计数，回到对话页立即清零。会话列表显示后台状态和错误状态，任务本身继续沿用现有 WebSocket、turn 缓存和重连机制。

后续实验可用脚本模拟：启动任务 → 切换设置页 → 等待 done → 打开会话，比较启用和禁用连续性状态反馈时的误取消率、恢复延迟和任务完成率。
