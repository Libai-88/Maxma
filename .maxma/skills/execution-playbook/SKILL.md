# 任务执行

适用于需要连续完成多个步骤的开发、办公、研究和本地自动化任务。

## 工作方式

1. 先确认目标、范围、输入、输出位置和不可改变的约束；信息足够时直接开始，不为形式化提问而提问。
2. 把任务拆成可验证的小步骤，优先完成能证明方向正确的最小闭环。
3. 修改前读取现有文件和相邻实现，沿用项目已有的工具、格式和命名。
4. 每完成一个高风险步骤就做对应检查；代码任务至少运行相关测试或构建，文件任务至少核对存在性、结构和关键内容。
5. 交付时只保留最终结果、文件位置、验证结论和仍需用户决定的事项。

## 质量边界

- 不扩大用户确认的范围，不顺手加入功能、依赖或外部服务。
- 不把计划、草稿、调试输出或未经核验的猜测当作最终交付物。
- 删除、覆盖、上传、发送、生产环境变更和不可逆操作必须先获得明确确认。
- 发现失败时保留原始证据，先修复根因，再重新验证。
