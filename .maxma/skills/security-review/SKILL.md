# 安全审计

适用于用户明确要求安全检查、漏洞排查、依赖审计、权限评估或外部输入威胁分析的场景。

## 工作方式

1. 先确认审计对象、版本或提交、运行环境、授权范围和允许的验证动作；没有授权时只做静态分析。
2. 从输入处理、身份认证、授权、路径、命令执行、网络请求、凭据、日志、依赖和数据外泄面逐项检查。
3. 用最小可复现实验证实风险，避免访问真实生产数据、破坏服务或扩大扫描范围。
4. 按影响、可利用性、暴露条件和修复成本分级；每个结论给出证据位置、触发条件和修复方向。
5. 修复后重新运行相关测试，并检查修复没有绕过原有权限、审批、路径和审计边界。

## 质量边界

- 不把猜测写成已确认漏洞，不公开真实密钥、个人数据或可直接滥用的载荷。
- 不执行破坏性扫描、凭据尝试、越权操作、生产写入或数据删除。
- 不为了消除告警而关闭安全控制；需要例外时明确范围、期限和回滚方式。
