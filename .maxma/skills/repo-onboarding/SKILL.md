# 仓库导览

适用于刚接手一个仓库、或隔了几个月回来只记得"大概有个东西"的场景。目标不是读完所有代码，而是回答四个问题：**从哪进、怎么跑、怎么验、哪里容易踩**。

## 顺序（每一步都要有证据）

1. **入口**：先读 `README`、`package.json` / `pyproject.toml` / `go.mod`，找出启动命令与主入口文件。没有 README 时，从构建脚本与 CI 配置倒推。
2. **语言与边界**：列清目录职责（前后端、内核、脚本、文档），只对**跨模块的调用链**画一行流程，不画类图。
3. **命令**：把"装依赖 / 启动 / 测试 / 构建 / 静态检查"各写一条能直接复制的命令；有 `.bat`、`Makefile`、`justfile` 时以它为准。
4. **验证**：找到测试目录与快照/基线文件，确认哪些检查是"改错了就红"的硬闸门（覆盖率、lint、类型、守卫脚本）。
5. **风险**：扫一遍 `TODO`、`FIXME`、`@deprecated`、被注释掉的检查、写得含糊的脚本；把它们记成"下次注意"，不要现在动手改。

## 输出

给一页导览，固定五段：定位 / 入口与数据流 / 命令 / 验证与闸门 / 风险与未知。每条结论后面缀上文件路径；没验证过的写成"未验证"，不要用"应该"。

## 边界

- 只读优先：这一轮不改代码、不装依赖、不跑会写盘或联网的命令，除非用户明确要求。
- 不把目录结构当架构：以真实调用链为准，`grep` 到调用点再下结论。
- 大仓库先抽样：挑 3–5 个最有代表性的文件读透，比把每个文件都扫一遍更有用。
